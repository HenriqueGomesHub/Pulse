### Why — the exact mechanism

`evolution()` ranks active strategies, filtering to `trades_30d >= MIN_CLOSED_TRADES (10)`, then:

```
if (ranked.length < MIN_QUALIFIERS)   // MIN_QUALIFIERS = 2
  → log, return; nothing proposed, no evolution_log rows
```

Per the table in §1, `ranked.length` was 0, 0, 0, 1, 1. **The gate returned before reaching Claude
on every cycle.** This is the loop behaving exactly as written; it is not a malfunction.

Three further locks sit behind it, each of which would independently have prevented a decision:

1. **Retirement is arithmetically impossible.** `retirementAllowed = active.length - 1 >=
   MIN_ACTIVE_STRATEGIES`. Active count has been 2 since birth; `MIN_ACTIVE_STRATEGIES = 3`.
   `2 − 1 = 1 >= 3` is false, permanently. Even a perfect candidate could only ever be *added*.
2. **Candidates can only be activated by the loop.** `reconcileFirability` promotes
   `candidate → active` only when `promoted_and_not_retired` — i.e. only when an `evolution_log`
   promote row already exists. With that table empty, seeds 2 and 4 can never become active.
3. **Which makes it circular.** The loop needs ≥2 active strategies trading ≥10/30 d. Only one
   active strategy trades. The two dormant seeds could supply the second, but only the loop can
   wake them, and the loop is gated on them.

### Floor events

`MIN_ACTIVE_STRATEGIES = 3`; the active count has been **2** for the entire month. The system has
been below its own floor since 2026-08-11 — not through any demotion, but because seeds 2 and 4
were born `candidate` and nothing has ever changed that. `warnInactiveSeeds()` warns about this on
every boot and `reconcileFirability` logs `FLOOR BREACHED` when demotions occur; both write to
Railway logs, not the database, so neither is visible here.

### One thing this database cannot tell you

Scheduled runs report via `heartbeat()` to Hub over HTTP; nothing is written locally. So whether
the Sunday cron actually fired is not answerable from this database. It also does not matter:
under the qualifier gate, a run that fires and a run that does not fire leave **identical (empty)**
traces. If you want to know, the evidence is in Hub's agent heartbeats for `evolution`.

## TOP 3 HYPOTHESES FOR NEGATIVE EXPECTANCY

Restated: expectancy is −3.71%/trade, not zero.

### H1 — There is no entry edge. The loss is the watchlist's beta, and the stop is what realises it. *(primary)*

**Evidence for.**

- The same 20 live entries, held passively and ignoring every exit rule, return **−3.80% at 5 days**
  (realised: −3.71%) and **−6.36% at 14 days**. Only 4 of 20 were up after 5 days. *The exits are
  not destroying value; the entries have none.*
- Watchlist baseline over the month: **−2.44% mean per 5-day window**, median −3.14%, only 26.6% of
  windows up (n = 323 symbol-days).
- 16 of 19 priced tickers fell over the month; equal-weight basket **≈ −12.8%**.
- Across all 105 seed-3 entry signals, the 5-day forward return is −0.47% to −2.74% depending on
  subset — indistinguishable from, or slightly worse than, drawing a random long from the same
  universe on a random day.

**What would confirm it.** Add excess-return-over-equal-weight-basket for each trade's actual hold
window. If excess expectancy is ≈ 0 while absolute expectancy is −3.7%, the strategy is a beta
machine and every threshold question is moot. Secondarily: replay the same entry block over a
flat-or-rising window and watch expectancy move with the tape.

**What would falsify it.** Excess-of-basket expectancy clearly positive while absolute expectancy is
negative — that would mean the entries do select, and we were simply long in a downtape.

### H2 — The system has one strategy, and the machinery built to fix that cannot run.

**Evidence for.**

- 20 of 23 closed trades come from a single strategy; the other 3 are a smoke test.
- Seed 1 fired 8 times in 31 days, all 8 price-excluded. Seed 2 would have fired 439 times but is
  not active. Seed 4's second leg fired once in 32,880 ticks.
- `evolution_log` and `evolution_rejections` are both empty after 5 scheduled cycles, because the
  qualifier gate needs 2 active strategies at ≥10 trades/30 d and there has only ever been 1.
- Candidates can only be woken by a promote the loop cannot issue; retirement is arithmetically
  impossible at 2 active against a floor of 3.
- Net effect: one un-diversified, never-challenged strategy ran unsupervised for a month while the
  correction mechanism sat behind a gate it could not open.

**What would confirm it.** On a scratch copy, activate seed 2 (or set `MIN_QUALIFIERS = 1`) and
